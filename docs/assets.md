# 三层图片体系与按需生成

图片是增强角色表达的可选资料，不是启用角色的门槛。日常可积极配一张语义贴合的图，文字完整；严肃、紧急、隐私、纯文字要求与发送失败时不强插。先用宿主已有的原生附件/生图能力，无需为了角色新装模型或脚本。

## 1. 形象基准（最高优先级）

`assets/reference/character-fullbody.webp` 保留用户提供的全身三视图原文件，含正面、侧面、背面和鲸尾连接细节。扩充Q版表情时，支持参考图且已获准使用的图像模型应**实际读取三视图，可加一张已确认的常用Q版原图**，不是只收到文字描述或文件名。没有参考图输入能力时不要声称严格保持身份；优先用现有原图。三视图负责角色辨识，常用Q版负责脸型、比例和画风。

这套素材是社区二创，不宣称来自 DeepSeek 官方，也不强制使用某个模型提供商。仓库不携带生图API key；使用何种合法可用的图像服务由宿主配置。

### 宿主已有生图能力时

先找基础库是否已有合适语义；确实需要新场景时再生成。提示可描述「同一鲸鱼娘，保持参考图的蓝色渐变头发、头饰、鲸尾与服饰辨识点，单角色正在认真核对资料，温和专注；单一动作、完整轮廓、透明背景，不加未经核对的字」。这是本包原创提示示例，不是原作者固定提示词。

生成后真实查看图片：人物是否一致、手尾/道具有无缺陷、文字是否准确、情绪是否适合当前回复。生成失败或不一致就用基础原图；缺合适图就文字。临时回复图不等于加入正式基础库，持久收录仍按下方审核规则。不能把图像生成成功说成附件已送达。

## 2. 常用表情（基础发送层）

- `assets/stickers/common/index.json`：33张已校准的**语义真源**，含meaning、usage、SHA256；文件名是历史标签，不替代语义。
- `variants.json`：逐张实际alpha统计与透明状态。21张含真实透明像素，12张是不透明原图。透明不是根据扩展名猜的。
- `usage.md`：分场景说明；`preview.html`：离线预览。
- 现有原件保持原Git对象身份；本次只实际查看和复核少量代表图，不声称重看了全部33张。当前没有把不透明图强行抠成残缺图片，也没有把白底/棋盘格图案当透明。

**优先级：语义与适用场景 → 确认的形象 → 真正透明背景 → 格式偏好。** 不为透明而误发表情。21张透明原件供默认优先选用；12张不透明原件仍可在明确合适场景使用。优先透明不意味着每个既有语义已有透明替代版。

### 新图/透明替代版的统一标准

1. 单张、单角色、单动作，主体、手和鲸尾不被裁断；推荐RGBA PNG。
2. 背景alpha真实为0，边缘合理抗锯齿，无白底残留、棋盘格实绘、明显色边；白围裙、头饰、眼白不能被误删除。
3. 以三视图和确认Q版强参考生成，不能凭归档杂图改写角色基准。
4. 保存原图；替代版本单独命名，在元数据记录 `variant_of`、方法、来源、SHA256、审核状态。不能覆写当前原图或静默改语义。
5. 在白、黑、蓝背景上检查轮廓/白色服饰/毛发/鲸尾；核对手、资料和道具接触关系；含文字时逐字检查。
6. **人工确认后**加入常用索引；新候选与归档都不自动晋升。不要为了凑全透明数量把未经确认的图当正式图。

## 3. 参考杂物间（可选归档）

`archive/reference-library/` 对应518张历史图片，可能混有杂图、文字梗、多格图和画风差异。它们未细分分类，只供后来者按具体需求挑选、研究或作为再生图辅助参考，不进入日常选图范围，也不保证都是合格表情。先读少量元数据，再实际打开候选，不按编号猜情绪、不随机自动发送；未知来源/语义/授权就保持未知。

为避免每次克隆携带约256MiB杂物间，Git中只放这一层的清单和说明，**所有518张原图片打包在同一私仓 Releases 的 `deepseek-chan-reference-attic-v1.0.0.zip`**。角色不需要这些归档图片即可使用。下面仅是维护者在明确需要完整归档时的可选操作，不是给普通使用者的配置步骤：

维护者下载前确认 Release、资产名和摘要来自同一已授权仓库；下载后核对已知 SHA256。不要直接解压到工作仓库或宿主配置目录：先检查 ZIP 条目无绝对路径、`..` 越界与链接，再解压到隔离目录并只取实际需要的候选。不要为一次参考查询批量下载约 256MiB 归档。

原来已排除/待人工审核的候选、历史错误候选和重复ZIP不在本发布中。
